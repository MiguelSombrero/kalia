# ADR-0065: Kalia has no beer pictures and no mark in its own app, so a beer is shown by its strength on its style colour, a person by initials, and the mark is a cellar rack

- **Status:** accepted
- **Date:** 2026-10-03

## Context

Kalia contained no images at all: a catalog where no beer has a picture, a
cellar that is rows of text, a profile with a name and a toggle. It had no
field to hold an image and, by [iteration 7.5 task 04](../tasks/iteration-7.5/04-imagery-iconography-and-the-mark.md)'s
constraints, none was coming from the seed data. Its mark, a snifter and a
serif wordmark, had been drawn in iteration 6.5 for the Keycloak pages and
appeared nowhere in the app; the app's favicon was still the Next.js skeleton's.
No icon existed anywhere, so every affordance was a word.

What can fill a beer's place is limited by what each surface knows about a
beer. The feed line carries only a beer's name and brewery. A catalog or
cellar row adds its style and ABV. Only the details page has the country.
User-uploaded photos are a likely later step ([backlog](../tasks/backlog.md)),
so whatever is chosen has to reserve a shape that a photo can later fill.

This was run under the `design-task` skill
([ADR-0062](0062-a-design-task-is-a-skill-and-a-marker.md)): directions built
as mockups, shown to the product owner, the choice recorded here. The identity
it sits in is [ADR-0064](0064-visual-identity-can-art-square.md).

## Decision

**Kalia draws no pictures of beers: a beer's slot is its strength set large on
its style colour, a person's is their initials in a hairline square, the
mark is a nine-cell cellar rack with one cobalt cell, and there are seven
hand-drawn icons for the few jobs a word cannot do.** This is direction C,
"Specimen", of the three the product owner chose between.

- **A beer's slot says only what the surface knows.** Where the ABV is known
  it is a band of the beer's style colour with the ABV as the large figure. In
  a list, where only the style is known, it is a thin strip of that colour
  beside the row. Where neither is known, as in the feed, nothing is drawn and
  the row is text. Layouts therefore reserve a band or a strip *when the data
  exists*, never a fixed picture box.
- **A person's slot is initials, with no colour.** Colour in this identity
  belongs to beers and to the one action, so two people are told apart by
  their initials alone. The slot is square.
- **Both slots are decorative.** The beer's strength and the person's name are
  always written beside them as text, so each slot is hidden from assistive
  technology rather than named.
- **The slots are the shapes an upload will later fill.** A 16:7 band for a
  beer and a square for a person. This ADR designs those shapes and not the
  uploads, which carry storage, moderation and a GDPR surface of their own.
- **Icons are drawn, not installed.** Seven of them (menu, close, search,
  plus, arrow, back, check), a 2 px line with butt ends on a 24 grid, in
  `components/ui/`. Everything else stays a word: navigation tabs, container
  type, edit, remove, visibility. An icon that stands alone carries an
  accessible name; one beside a word is hidden. The toast's two state icons use
  this set.
- **The mark is a rack, not a glass.** Nine square cells, eight ink and one
  cobalt: the cellar the product is built around, and a favicon that survives
  16 px. Beside it the wordmark is quiet, normal-width capitals set widely
  tracked. The mark exists as a component the app can render, so it no longer
  lives only under `keycloak/themes/`. Which form the page header holds, and
  where it sits, is [task 06](../tasks/iteration-7.5/06-page-shell.md)'s.
- **The favicon is an SVG, with generated PNGs beside it.** The Next.js
  default `favicon.ico` is removed; an SVG serves the tab, a 32 px PNG serves
  browsers that ignore an SVG there, and a 180 px PNG serves iOS. Both PNGs are
  generated at build from the same drawing, so no raster file is tracked and the
  raster check's allowlist stays empty.
- **No API changes.** The feed stays without a style or ABV, so a feed line
  shows no beer imagery. Adding them to the feed is a backend change outside
  this iteration.

## Alternatives considered

**A, "Label".** Every beer a 4:5 can-label tile: a style-colour field, the
brewery's first letter cropped huge across it, the ABV in the corner. People
as initials on one of four coloured grounds, solid icons beside nearly every
word, a solid snifter for the mark. The most image-forward direction, and the
catalog read like a shelf of cans. Rejected for C. Its cost was that the feed
could not show a style, so the same beer was coloured in the catalog and grey
in the feed, and every row gained a tile column.

**B, "Primitives".** A beer a 2 × 2 composition of the mark's own shapes
(discs, quarter-discs, bars), generated by hashing name and brewery, with the
style group setting the palette; people the same kit mirrored; light outline
icons for kinds of things while buttons stayed words; a half-disc glass for
the mark. Rejected for C. A generated pattern says "this is one particular
beer" and nothing else, so it is decoration that costs a tile in every row,
and renaming a beer would change its picture.

**D, "Specimen with loud icons".** C unchanged except for the icons: 18 of them
instead of seven, heavy and solid, 24 to 32 px, over each navigation tab,
on every action, beside every container type, and as a marker on each feed
line. Built at the product owner's request after seeing C and rejected for C.
Its costs were a phone navigation tab 24 px taller, 18 drawings to keep
consistent, and three loud things on a page competing: the figure, the icons
and the mark. The product owner did not give a further reason.

**An icon library** (Lucide, Heroicons or a font). Rejected without being
built: [ADR-0021](0021-design-tokens-ui-primitives.md)'s no-new-dependency rule
for `components/ui/` has two exceptions, both for behaviour, and an icon is
appearance.

**A tracked PNG for the apple-touch icon.** iOS does not accept an SVG touch
icon, so a raster is needed one way or another. A committed file would put a
directory into `scripts/check-no-raster-images.mjs`'s allowlist, which is meant
to stay empty so a capture can never be committed by accident
([ADR-0062](0062-a-design-task-is-a-skill-and-a-marker.md)). Generating it
from the same drawing at build time avoids both. It costs three raw colour
values, because the generator cannot read CSS variables.

**Keeping the Keycloak snifter as the mark.** The glass carried across at no
cost, but it is drawn in iteration 6.5's palette and serif face, which
[ADR-0064](0064-visual-identity-can-art-square.md) replaced. C's rack replaces
it, and [task 11](../tasks/iteration-7.5/11-keycloak-pages-carry-the-identity.md)
carries the rack across.

## Consequences

- Good, because the app has a mark of its own that works at 16 px, a favicon
  that is no longer the framework's, and an icon set it controls.
- Good, because every slot is honest about its data: nothing is drawn that
  the surface cannot back, so there is no grey placeholder standing in for a
  picture that does not exist.
- Good, because the slots are reserved by shape, so a photo can later fill the
  band or the square without moving anything around it.
- Bad, because the feed shows no beer imagery. A front page of sentences stays
  a column of sentences, and that part of the audit's finding is answered by
  type and spacing in [task 07](../tasks/iteration-7.5/07-front-page-layout.md)
  and not by pictures.
- Bad, because a page of lists risks reading as a spreadsheet. Hierarchy has to
  come from the display face and white space alone.
- Bad, because two people are told apart only by their initials, and many
  usernames share one.
- Bad, because with so few icons the weight sits on labels, which Finnish
  capitals make about 30 % longer; a phone toolbar of three words is the
  tightest case.
- Neutral, because the mark's three raw colour values live in `lib/kaliaMark.ts`
  and `app/icon.svg`, which cannot read CSS variables. A test ties both to
  `globals.css`'s primitives, but [task 05](../tasks/iteration-7.5/05-token-only-styling-enforced.md)'s
  rule has to name them as exceptions.
- Neutral, because the Keycloak pages keep the snifter until task 11 replaces
  it, so for now the two origins show different marks.
- **Revisit trigger:** the feed carrying a style and ABV would let its lines
  show the same band or strip as the catalog; user-uploaded photos arriving
  should make the band and the square their frames.

## Evidence

**What the surfaces know about a beer**, read from the generated API types
(`frontend/lib/api/generated/models`) on 2026-10-03: a feed line has
`username`, `beerName` and `brewery` (a name), nothing else; a catalog or
cellar summary has `name`, `style`, `abv` and the brewery's name; only the
details page has the country and city. That is why the band needs the ABV and
the strip needs the style, and why the feed draws neither.

**Contrast of what the mark adds**, computed by `node scripts/check-contrast.mjs`
on 2026-10-03. The mark's one accent cell sits on the page, a non-text pairing
that was not declared before and now is, in `docs/design.md`:

| Pairing | Ratio | Needs |
|---|---|---|
| primary on background (the mark's cobalt cell) | 8.42:1 | 3:1 |
| foreground on background (the mark's ink cells, a person's initials) | 18.73:1 | 3:1 and 4.5:1 |
| style-foreground on style, every group (the band's figure) | 5.45 to 18.69:1 | 4.5:1 |

**The locale proxy swallowed the generated icons.** Next.js 16.3.6 emits
`<link rel="apple-touch-icon" href="/apple-icon?<hash>">` and, for a numbered
generated icon, `<link rel="icon" href="/icon1?<hash>">`, neither with a file
extension. `proxy.ts` excluded only paths containing a dot, so with the
generated routes added and the matcher unchanged, `curl -D -` on each returned
`HTTP/1.1 307 Temporary Redirect` to a locale path that does not exist. After
the matcher named the `icon`, `icon<n>` and `apple-icon` family, all three icon
URLs the page links to returned `200` with `image/svg+xml`, `image/png` and
`image/png`. `proxy.test.ts` asserts it with Next's own
`unstable_doesMiddlewareMatch`, and fails on the unchanged matcher;
`e2e/app-icons.spec.ts` follows the links the page emits.

**The icons decode in a browser under the real CSP.** In the desktop app's
browser pane, against the dev server, the `icon` and `apple-touch-icon` URLs
loaded as images (150 × 150 for the SVG, 180 × 180 for the PNG) and sampled
from a canvas gave `rgb(43,55,201)` in the top-right cell, `rgb(18,18,18)` in
its neighbour and `rgb(255,255,255)` in the gap, which are `--cobalt-700`,
`--ink-950` and `--white`. `img-src` is `'self' blob: data:`; nothing in this
change loads from another origin.

**`/favicon.ico` after the file is removed** answers `200 text/html`, the
not-found page, exactly as any unknown dotted path does (`/zzz.png` behaves the
same): the proxy skips paths with an extension, so they fall to the root
not-found. This predates the change. The page's own `<link>` tags are what
browsers follow.
