# Architecture decision records

Every decision in this directory records **why** something was chosen and what
was rejected to get there ([ADR-0020](0020-documentation-roles.md)). For the
*shape* of the system read [docs/architecture.md](../architecture.md); for
*how* to work in either app read the two READMEs.

- **Format:** [template.md](template.md), with the rules in
  [ADR-0019](0019-adr-format-and-conventions.md).
- **When a decision earns an ADR at all:**
  [ADR-0032](0032-when-a-decision-earns-an-adr.md) — a credible alternative
  was rejected, and the reason would not survive in the code,
  `architecture.md` or a README.
- **The authoritative index** — title, status and date for every ADR — is
  [docs/architecture.md §9](../architecture.md#9-architecture-decision-records).
  This file groups the same set by subject so a related run of decisions can
  be read as one; it is deliberately not a second copy of the titles.

`scripts/check-adrs.mjs` runs in CI and fails if an ADR is missing from either
index.

## Foundations

The shape of the system, decided at the start and not revisited since.

- [ADR-0001](0001-monorepo.md) — one repository holds both apps.
- [ADR-0002](0002-spring-modulith.md) — one Spring Boot deployable of
  Modulith modules, not microservices.
- [ADR-0003](0003-bff-pattern.md) — the browser talks only to Next.js, which
  calls the Spring API server-side.

## Product scope and sequencing

What gets built, in what order, and what is deliberately deferred.

Kalia's own store flow was designed here and then removed from the product
entirely. Nothing replaces the two deprecated records — Kalia does not sell
beer, and that is a [backlog](../tasks/backlog.md) line rather than a decision
anyone is making. Read them for the lesson they carry, amended into
[ADR-0032](0032-when-a-decision-earns-an-adr.md): an ADR written for work
nobody has committed to becomes a constraint anyway.

- [ADR-0004](0004-backend-cart.md) — the cart is a backend domain module, not
  frontend session state. *(Deprecated: there is no cart.)*
- [ADR-0005](0005-defer-auth-mock-payments.md) — defer auth, mock the payment
  provider. *(Deprecated: auth shipped, and there are no payments.)*
- [ADR-0006](0006-cellar-first.md) — authentication then the personal cellar.
  *(Amended: the store and reviews questions it defers are closed.)*

## Frontend structure and conventions

- [ADR-0008](0008-tanstack-query.md) — TanStack Query is the mandatory data
  layer for client components.
- [ADR-0009](0009-zustand-ui-state.md) — three homes for client state: query
  cache, URL params, Zustand. Read with ADR-0008; the two halves of one split.
- [ADR-0010](0010-react-hook-form-zod.md) — react-hook-form + Zod for
  validated forms; URL-driven GET filters stay native.
- [ADR-0011](0011-i18next-localization.md) — i18next with locale-prefixed
  URLs; Finnish is a full peer of English, plural grammar included.
- [ADR-0012](0012-orval-api-client.md) — the API client is generated by orval
  from the backend's live OpenAPI spec, with a CI drift check.
- [ADR-0021](0021-design-tokens-ui-primitives.md) — two-layer CSS tokens plus
  three shared primitives, no new dependency.
- [ADR-0022](0022-loading-error-empty-states.md) — per-route skeletons shaped
  like the page, one error boundary at the locale root.
- [ADR-0023](0023-typed-api-failures.md) — every `kaliaFetch` failure is a
  tagged `ApiError`; a non-2xx status deliberately is not one.

## Authentication and identity

Six independent decisions, in the order they were made — later ones fix
defects the earlier ones created, which is why they stay separate documents
([ADR-0032](0032-when-a-decision-earns-an-adr.md)). For the design as a whole
in one place, read
[docs/architecture.md §6](../architecture.md#6-authentication-and-identity).

- [ADR-0025](0025-authjs-valkey-adapter.md) — Auth.js with a hand-written
  Valkey adapter for Keycloak OIDC, and the public/internal Keycloak address
  split the compose stack forces.
- [ADR-0028](0028-resource-server-and-current-user.md) — the backend validates
  bearer tokens itself and the Keycloak `sub` is the canonical user id.
- [ADR-0029](0029-silent-token-refresh.md) — renew access tokens lazily;
  `invalid_grant` — and only `invalid_grant` — ends the local session.
- [ADR-0030](0030-per-session-token-storage.md) — a token set belongs to one
  session, not one user, so sign-out ends the right device's SSO session.
- [ADR-0031](0031-backchannel-logout.md) — Keycloak tells Kalia a session
  ended too: an unauthenticated endpoint validates the Logout Token's
  signature and ends the local session matching its `sid`.
- [ADR-0033](0033-keycloak-account-relinking.md) — a stale account index
  (Keycloak's `sub` changed, e.g. on a dev realm reimport) re-links by email
  instead of locking the user out, since Keycloak is the only provider.

## Configuration, security and operations

- [ADR-0015](0015-configuration-strategy.md) — environment variables, not
  Spring profiles; one `application.properties` with safe defaults.
- [ADR-0016](0016-security-response-headers.md) — security headers in
  `next.config.ts`, CSP in its no-nonce form.
- [ADR-0018](0018-frontend-env-var-validation.md) — a production frontend
  missing a required variable aborts at startup instead of failing every call.
- [ADR-0024](0024-dependency-vulnerability-scanning.md) — Trivy fails CI on
  fixable HIGH/CRITICAL findings; Dependabot opens the updates.

## Engineering process and documentation

How the project works on itself. This project is process-first by design
(`CLAUDE.md`), so these are on-mission rather than overhead — but they are the
category with no external limit on its growth, which is what ADR-0032 exists
to bound.

- [ADR-0017](0017-code-comment-policy.md) — a comment earns its place only by
  carrying what the repository cannot.
- [ADR-0019](0019-adr-format-and-conventions.md) — the five-section ADR
  structure, and why alternatives and costs get their own headings.
- [ADR-0020](0020-documentation-roles.md) — ADRs record why, architecture.md
  records shape, READMEs record how; every other mention is a pointer.
- [ADR-0026](0026-task-file-format.md) — one file per task, with acceptance
  criteria that include tests.
- [ADR-0027](0027-process-weight.md) — implement directly by default; heavier
  process must earn its place against the task.
- [ADR-0032](0032-when-a-decision-earns-an-adr.md) — when a decision earns an
  ADR, and why related decisions are grouped by this index rather than merged.
- [ADR-0034](0034-agent-context-layout.md) — `backend/` and `frontend/` each
  carry a `CLAUDE.md` importing their README, so the conventions load with the
  subtree; and which monorepo optimizations this repository declines.
