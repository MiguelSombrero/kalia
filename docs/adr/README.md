# Architecture decision records

Every decision in this directory records **why** something was chosen and what
was rejected to get there ([ADR-0020](0020-documentation-roles.md)). For the
*shape* of the system read [docs/architecture.md](../architecture.md); for
*how* to work in an app read its README ([backend](../../backend/README.md),
[web](../../web/README.md), [mobile](../../mobile/README.md)).

- **Format:** [template.md](template.md), with the rules in
  [ADR-0019](0019-adr-format-and-conventions.md).
- **When a decision earns an ADR at all:**
  [ADR-0032](0032-when-a-decision-earns-an-adr.md) — a credible alternative
  was rejected and the reason would not survive in the code,
  `architecture.md` or a README; it binds work now, since a possibility being
  carried is a backlog item; and a reader who wasn't already going to open the
  task file that made it would need to find it.
- **The authoritative index** — title, status and date for every ADR — is
  [All ADRs by number](#all-adrs-by-number), at the end of this file. The
  sections between group the same set by subject so a related run of
  decisions can be read as one; they are deliberately not a second copy of the
  titles. The few decisions that define the system are listed in
  [docs/architecture.md §9](../architecture.md#9-architecture-decision-records).

`scripts/check-adrs.mjs` runs in CI and fails if an ADR is missing from the
table or from the subject sections.

## Foundations

The shape of the system, decided at the start and not revisited since.

- [ADR-0001](0001-monorepo.md) — one repository holds both apps. Amended by
  ADR-0092 below.
- [ADR-0002](0002-spring-modulith.md) — one Spring Boot deployable of
  Modulith modules, not microservices.
- [ADR-0003](0003-bff-pattern.md) — the browser talks only to Next.js, which
  calls the Spring API server-side.
- [ADR-0092](0092-the-repository-is-plain-npm-workspaces-of-web-mobile-and-two-packages-that-ship-typescript-source.md)
  — the repository is plain npm workspaces of `web/`, `mobile/` and two
  packages that ship TypeScript source, with one root lockfile; amends
  ADR-0001.
- [ADR-0094](0094-the-mobile-app-is-expo-as-a-development-build-with-generated-native-projects-and-no-paid-service.md)
  — the mobile app is Expo as a development build, its `ios/` and `android/`
  generated by `expo prebuild` and never committed; Expo Router, strict
  TypeScript, the web's data, state, form and i18n conventions by pointer, and
  no paid service on the build or run path.

## Catalog

- [ADR-0077](0077-the-catalog-is-seeded-once-from-wikidata-and-owned-by-kalia.md)
  — the catalog is seeded once from a pinned Wikidata snapshot and owned by
  Kalia from then on. It takes facts only, nothing from Untappd. Every row
  records its source, and Wikidata's Untappd-derived provenance is an openly
  accepted risk.
- [ADR-0078](0078-catalog-reads-over-budget-for-want-of-an-index-stay-uncached.md)
  — the catalog stays uncached. What broke 300 ms at 150k beers lacked an
  index, or had a defect already recorded elsewhere. The question reopens past 150k
  beers.
- [ADR-0079](0079-a-brewerys-country-is-an-iso-code-named-in-the-readers-language-by-the-runtime.md)
  — a brewery's country is stored as an ISO 3166-1 code that every client
  names in its reader's language from the runtime's CLDR data. A brewery
  whose imported country has no code maps to where it stood, today.
- [ADR-0087](0087-the-brewery-list-is-cut-in-sql-by-a-stored-key-in-the-java-name-order.md)
  — the brewery list and search are cut in SQL by a stored, indexed name key
  that keeps the Java sort's order in every environment.
- [ADR-0091](0091-a-contributed-catalog-entry-waits-for-an-operator-and-no-catalog-row-is-ever-deleted.md)
  — a contributed beer or brewery is seen by its contributor alone until an
  operator approves it, the number waiting per contributor is capped, and no
  catalog row is ever deleted, so cellar entries and feed lines keep what they point at.
- [ADR-0102](0102-a-suggestion-is-a-pending-beer-with-its-new-brewery-and-an-admin-reviews-it-inside-catalog-which-publishes-one-event-per-decision.md)
  — a suggestion is a pending beer with the brewery added with it; an admin
  approves, rejects or edits it through an admin API inside `catalog`, which
  keeps a review record and publishes one event per decision.

## Cellar

- [ADR-0034](0034-cellar-two-level-bottle-model.md) — the cellar holds one row
  per bottle, owned by an entry per (user, catalog beer); quantity is always
  derived, never a stored count.
- [ADR-0052](0052-cellar-aggregate-owns-its-writes.md) — a bottle is created,
  changed and removed only through its entry, every write ends in a `save` on
  the root, and there is no `BottleRepository`; a violated bottle rule is a
  `cellar.domain` exception from the point it is raised.
- [ADR-0053](0053-cellar-domain-events-on-the-aggregate-root.md) — a cellar
  domain event is registered on the aggregate root and drained by Spring Data
  on `save`, never published from a service; it carries ids and a timestamp,
  never a mutable copy, and is named as a past participle on the thing that
  changed (`BottleAdded`).
- [ADR-0083](0083-a-cellar-read-is-joined-with-its-beers-in-the-backend.md)
  — both cellar reads arrive with each entry joined to its beer through
  `CatalogApi`, empty and unresolvable entries left out in one place, and a
  feature's `api.ts` reaches only its own generated tag.

## Feed

- [ADR-0058](0058-feed-event-recording-model.md) — feed's listener is
  idempotent on a dedicated event id (not a natural key), the event carries
  no `entryId` because it isn't reliably available yet when the event is
  registered, and `FeedLine` freezes quantity and vintage from the event
  rather than ever reading `cellar` live.
- [ADR-0059](0059-feed-respects-cellar-visibility.md) — a cellar that is not
  public contributes no line, named or unnamed; the rule is a single
  read-time filter, never a write-time check or a purge; and it amends
  ADR-0050 now that a feed makes public cellars discoverable.
- [ADR-0060](0060-feed-delivery-is-polling.md) — the front-page feed reaches
  an already-open browser by polling through a Server Action, not a stream;
  no new route-handler kind, no CSP change, no instance-affinity limitation
  to accept.
- [ADR-0081](0081-incomplete-event-publications-are-resubmitted-five-times-and-completed-ones-deleted.md)
  — an event publication whose listener has not completed is resubmitted at
  startup and every minute, five attempts at most, by Kalia's own component
  rather than Modulith's restart property. A completed publication is
  deleted.

## Notifications

- [ADR-0103](0103-a-contributor-is-told-what-became-of-a-suggestion-by-a-notification-that-a-new-module-keeps-until-they-acknowledge-it-and-then-deletes.md)
  — a new `notification` module keeps one notification per review decision,
  written by an idempotent listener on `SuggestionReviewed` that freezes the
  decision's facts. The contributor acknowledges each on its own and the row is
  deleted then; an unread one never expires; the web reads the unread count once
  per signed-in page render.
- [ADR-0106](0106-a-contributors-unread-notifications-are-one-signal-in-the-sticky-bar-that-opens-a-panel-over-the-page.md)
  — a contributor's unread notifications are one signal in the sticky bar on
  every signed-in page, absent with nothing unread, which opens a panel over
  the page where each is acknowledged on its own and an edit shows as the name
  pair.

## Profiles and public cellars

What a user is to other users, and how the one thing they can publish is
addressed. The first decides the identifier, the second the URL built on it,
and the third keeps that identifier from ever passing to someone else.

- [ADR-0049](0049-profile-module-and-public-identity.md) — a `profile` module
  holds the user-facing identity: the Keycloak username copied once and
  immutable, plus a cellar-visibility flag defaulting to private.
- [ADR-0050](0050-public-cellar-addressing.md) — a public cellar lives at one
  locale-less URL, answers 404 when it is not public, and is never indexed.
  Amended by [ADR-0059](0059-feed-respects-cellar-visibility.md): "anyone with
  the link" no longer means only whoever the owner told directly, now that a
  feed hands the link to every front-page visitor.
- [ADR-0080](0080-a-username-is-unique-regardless-of-case-and-never-reused.md)
  — a username belongs to one profile ever, compared regardless of case. A
  departed account's name stays reserved, and a newcomer whose Keycloak
  username is held is told the name is taken.
- [ADR-0104](0104-deleting-an-account-deletes-what-is-the-users-own-unlinks-what-is-shared-and-leaves-a-tombstone-of-the-folded-username.md)
  — deleting an account deletes its cellar, entries, feed lines and
  notifications, removes its id from the catalog rows and review records that
  must stay, and leaves a tombstone of the folded username with no `sub`.

## Backend structure and conventions

- [ADR-0007](0007-backend-package-structure.md) — DDD-lite layers
  (`domain`/`application`/`web`) inside each module, enforced by ArchUnit.
- [ADR-0013](0013-logging-conventions.md) — SLF4J via `@Slf4j`, parameterized
  calls, and what each level means.
- [ADR-0014](0014-shared-exception-handling.md) — one shared advice handling
  only the two cases Spring Boot reports without field-level detail, and every
  error the API sends is a declared type.
- [ADR-0036](0036-pre-deployment-migration-edits.md) — before Kalia is
  deployed anywhere, an applied Flyway migration may be edited directly
  rather than reversed forward.
- [ADR-0042](0042-bounded-request-parameters.md) — every request parameter is
  bounded by a named constant; a constraint spanning two parameters is
  checked in the handler and reported through `detail`.
- [ADR-0044](0044-catalog-search-indexes.md) — catalog name search keeps
  substring matching and a `pg_trgm` trigram index serves it; the style and
  country filters get indexes on `lower(...)`.
- [ADR-0045](0045-brewery-list-paginates-in-application.md) — the brewery list
  gains a `page`/`size` contract but keeps loading and sorting the full table
  in Java, so its name order stays locale-independent. Superseded by
  [ADR-0087](0087-the-brewery-list-is-cut-in-sql-by-a-stored-key-in-the-java-name-order.md).
- [ADR-0057](0057-retry-on-constraint-violation-for-get-or-create.md) — a
  get-or-create write retries once on its own unique-constraint violation via
  Spring Framework's native `@Retryable`, each attempt its own transaction.
- [ADR-0093](0093-the-api-is-additive-only-while-an-app-is-installed-and-a-committed-spec-fails-a-breaking-diff.md)
  — `/api/v1` changes additively only while an app is installed: a breaking
  change is a new path beside a deprecated one, retired once task 12's minimum
  build excludes every build that uses it, and a committed OpenAPI spec fails a
  test on drift and a CI job on a breaking diff, which stays advisory until
  the app is distributed beyond the product owner's own phone.

- [ADR-0067](0067-page-shell-sticky-bar-and-page-component.md) — every page

- [ADR-0105](0105-the-admin-reviews-suggestions-in-a-queue-beside-the-suggestion-and-rejects-through-a-dialog-that-asks-for-the-reason.md)
  — the admin review page is a queue with the suggestion beside it; editing is
  a mode of the suggestion, approving is one click, and rejecting asks in a
  dialog where the mandatory reason is chosen.
- [ADR-0068](0068-front-page-one-column-cellar-or-pitch-above-a-ruled-feed.md)
  — the front page is one column: the pitch or the visitor's cellar above a

- [ADR-0069](0069-catalog-one-ruled-column-beside-a-filter-column-with-one-search-button.md)
  — the catalog is one column of ruled rows beside a filter column that folds
  on a phone under one Search button; a beer's page is its band and linked facts.
- [ADR-0070](0070-cellar-sortable-beers-beside-their-band-with-bottle-tiles-headed-by-vintage.md)
  — the cellar is a sortable list of beers beside their style band, every
  bottle a tile headed by its vintage; the owner's read carries all bottles.
- [ADR-0071](0071-profile-a-name-tag-over-two-visibility-choices-and-one-error-style.md)
  — the profile is a name tag above two visibility choices that list what they
  show, going public asks first, saves report in a toast; one error style app-wide.
- [ADR-0072](0072-the-mark-is-a-bottle-pouring-into-foam-on-a-teal-tile.md)
  — the mark is a coral-lined bottle pouring beer into foam on a deep teal
  tile, in colours of its own that nothing else in the app uses.
- [ADR-0073](0073-components-ui-stays-the-apps-own-primitives-not-a-design-system.md)
  — no design system, package or component catalogue: `components/ui/` stays
  the web app's own, and a look that recurs becomes a primitive, not a rule.
- [ADR-0075](0075-the-accessibility-bar-is-wcag-2-2-aa.md) — the bar is WCAG
  2.2 AA: axe scans at its tags, and Playwright asserts focus never hides
  under a sticky bar along three keyboard flows.
- [ADR-0082](0082-a-beer-is-added-over-the-search-that-missed-it-and-a-pending-button-stays-legible.md)
  — a beer is added in a dialog over the search that missed it, landing on a
  search that finds it; a button sending its form fades to 75 %, still AA.
- [ADR-0022](0022-loading-error-empty-states.md) — per-route skeletons shaped
  like the page, one error boundary at the locale root.
- [ADR-0023](0023-typed-api-failures.md) — every `kaliaFetch` failure is a
  tagged `ApiError`; a non-2xx status deliberately is not one.
- [ADR-0037](0037-functional-modules.md) — no hand-written classes:
  discriminated unions and type guards over polymorphism, factory functions
  over constructors for DI, `type` over `interface`.
- [ADR-0040](0040-client-reads-via-server-actions.md) — a client component's
  read of authenticated data calls a Server Action, not the generated client
  directly, so the token-lookup chain never enters the browser bundle.
- [ADR-0041](0041-tanstack-query-feature-owned-hooks.md) — a component calls
  a feature-owned hook (`useAddBottle`) wrapping `useQuery`/`useMutation`,
  never those TanStack Query hooks directly.
- [ADR-0096](0096-mobile-unit-tests-run-on-jest-and-end-to-end-flows-on-maestro-with-android-the-only-ci-platform.md)
  — the mobile app's unit tests are Jest with React Native Testing Library and
  its end-to-end flows are Maestro; CI runs the flow on Android only, against
  the full stack, and iOS runs it locally through `make verify`.
- [ADR-0099](0099-the-android-end-to-end-build-caches-no-native-output-because-neither-ccache-nor-cmakes-output-saves-three-minutes.md)
  — the Android end-to-end job caches no native build output: ccache saved
  1:45 of the build step, short of the three-minute bar, and a cached CMake
  output made it slower.

## Authentication and identity

Thirteen independent decisions, in the order they were made — later ones fix
defects the earlier ones created, which is why they stay separate documents
([ADR-0032](0032-when-a-decision-earns-an-adr.md)). For the design as a whole
in one place, read
[docs/architecture.md §6](../architecture.md#6-authentication-and-identity).

- [ADR-0025](0025-authjs-valkey-adapter.md) — Auth.js with a hand-written
  Valkey adapter for Keycloak OIDC, and the public/internal Keycloak address
  split the compose stack forces.
- [ADR-0028](0028-resource-server-and-current-user.md) — the backend validates
  bearer tokens itself and the Keycloak `sub` is the canonical user id.
- [ADR-0029](0029-silent-token-refresh.md) — renew access tokens lazily;
  `invalid_grant` — and only `invalid_grant` — ends the local session.
- [ADR-0030](0030-per-session-token-storage.md) — a token set belongs to one
  session, not one user, so sign-out ends the right device's SSO session.
- [ADR-0031](0031-backchannel-logout.md) — Keycloak tells Kalia a session
  ended too: an unauthenticated endpoint validates the Logout Token's
  signature and ends the local session matching its `sid`.
- [ADR-0033](0033-keycloak-account-relinking.md) — a stale account index
  (Keycloak's `sub` changed, e.g. an admin recreating a user) or a sign-in
  through a different Auth.js provider entry for the same Keycloak account
  re-links by email instead of locking the user out, since every entry
  shares one identity source.
- [ADR-0043](0043-createuser-race-safety.md) — `createUser` claims the email
  index with `SET NX`; a losing concurrent first sign-in waits on the winner's
  record instead of orphaning its own.
- [ADR-0055](0055-self-registration-via-keycloak.md) — a visitor registers
  entirely inside Keycloak's own flow, reached through a second Auth.js
  provider pointed at its registration endpoint; no admin credential in the BFF.
- [ADR-0056](0056-branded-bilingual-keycloak-pages.md) — Keycloak's pages get a
  minimal `keycloak.v2` theme and the realm's own `en`/`fi` internationalisation;
  the sign-in actions pass `ui_locales`, and Kalia writes no auth-page
  translations of its own.
- [ADR-0061](0061-brute-force-lockout-is-temporary-and-disclosed.md) — repeated
  failed sign-ins lock an account temporarily, never permanently, and the
  kalia theme overrides Keycloak's own generic lockout message to say so.
- [ADR-0074](0074-keycloak-pages-one-open-column-under-the-lockup-with-a-palette-drift-check.md)
  — Keycloak's pages drop the card for one narrow column under Kalia's lockup,
  which links home; a `scripts/` check holds the theme's colours and mark to
  the app's.
- [ADR-0095](0095-the-mobile-app-signs-in-as-a-public-pkce-client-holds-an-offline-token-and-calls-spring-directly-through-the-edge.md)
  — the mobile app signs in through the system browser as a public PKCE
  client, holds an offline token in secure storage and calls Spring directly
  through the edge; amends ADR-0003 and ADR-0029.
- [ADR-0101](0101-an-admin-is-a-realm-role-in-the-access-token-which-the-backend-enforces-on-one-path-prefix-and-the-web-reads-in-its-bff.md)
  — an admin holds the realm role `admin`, which the access token carries: the
  backend refuses everyone else with `403` on `/api/v1/admin/**`, the web
  answers everyone else with its not-found page, and the local stack seeds a
  development admin; a deployment's first admin is left undecided.

## Configuration, security and operations

- [ADR-0015](0015-configuration-strategy.md) — environment variables, not
  Spring profiles; one `application.properties` with safe defaults.
- [ADR-0016](0016-security-response-headers.md) — security headers in
  `next.config.ts`, CSP in its no-nonce form.
- [ADR-0018](0018-frontend-env-var-validation.md) — a production frontend
  missing a required variable aborts at startup instead of failing every call.
- [ADR-0024](0024-dependency-vulnerability-scanning.md) — Trivy fails CI on
  fixable HIGH/CRITICAL findings; Dependabot opens the updates.
- [ADR-0054](0054-keycloak-config-cli-realm-management.md) — keycloak-config-cli,
  not Keycloak's own placeholders, resolves per-environment realm values and
  re-applies the committed realm file on every boot.
- [ADR-0085](0085-runtimes-follow-long-term-support-not-the-newest-major.md) — Java and Node
  follow their long-term-support releases; Dependabot ignores semver-major
  bumps of those two images.
- [ADR-0088](0088-both-tiers-log-json-and-share-a-trace-id-and-count-failures-without-a-viewer.md)
  — both tiers log JSON and share a W3C trace id, and failures are counted by
  Micrometer and `@prometheus-io/client` behind a token, with no viewer added to the
  stack.
- [ADR-0089](0089-a-deployment-cannot-inherit-a-dev-credential-because-the-base-compose-file-demands-every-secret.md)
  — `docker-compose.base.yml` is the deployable definition and requires every
  secret; the local stack adds the dev values, the seed service and the Swagger
  client around it.
- [ADR-0090](0090-an-nginx-edge-proxy-bounds-the-anonymous-edges-and-names-the-client-address-the-services-trust.md)
  — an nginx edge proxy is the only published service: it limits requests and
  bodies per client address in front of the frontend, backend and Keycloak, and
  names the client address they trust.
- [ADR-0097](0097-a-phone-reaches-the-stack-over-the-owners-tailnet-in-an-opt-in-phone-mode-where-one-origin-is-the-issuer.md)
  — a physical phone reaches the stack over the owner's tailnet in an opt-in
  phone mode, where one origin is the issuer Keycloak stamps and every consumer
  validates; plain HTTP until a recorded trigger; amends ADR-0095.
- [ADR-0098](0098-an-installed-builds-errors-are-read-from-the-devices-own-logs-and-a-crash-service-waits-for-a-second-user.md)
  — an installed build's errors are read from the device's own logs
  (Console.app or Xcode, `adb logcat`) and a crash service is deferred until
  someone other than the product owner installs Kalia; no endpoint receives
  client errors.
- [ADR-0100](0100-postgres-has-three-roles-one-that-owns-the-schema-for-flyway-one-that-reads-and-writes-rows-and-one-for-keycloak.md)
  — Postgres has three roles: an owner Flyway uses, a runtime role that reads
  and writes rows and cannot change the schema, and Keycloak's own; the
  superuser belongs to Postgres alone.

## Engineering process and documentation

How the project works on itself. This project is process-first by design
(`CLAUDE.md`), so these are on-mission rather than overhead — but they are the
category with no external limit on its growth, which is what ADR-0032 exists
to bound.

- [ADR-0017](0017-code-comment-policy.md) — a comment earns its place only by
  carrying what the repository cannot.
- [ADR-0019](0019-adr-format-and-conventions.md) — the five-section ADR
  structure, and why alternatives and costs get their own headings.

## All ADRs by number

Add a row when adding an ADR, in the table it belongs to. Its title, status
and date cells are copied from the ADR by `scripts/sync-indexes.mjs`, so a
status is changed in the ADR, never here
([ADR-0076](0076-index-cells-are-synced-from-their-files.md)). New ADRs follow
[template.md](template.md); the format and the rules behind it are
[ADR-0019](0019-adr-format-and-conventions.md), and what earns an ADR in the
first place is [ADR-0032](0032-when-a-decision-earns-an-adr.md).

The table is split in two because the two sets grow for different reasons:
decisions about the product, and decisions about how the project works on
itself. The status column holds the vocabulary token only. What superseded or
amended a decision is recorded in that ADR's own `Supersedes` /
`Superseded-by` / `Amended` fields, so it lives in exactly one place.

`scripts/check-adrs.mjs` runs in `make check` and fails an ADR with no row here
or no entry in the subject sections above, a row with no file, and an ADR
following the template with no `Bad` or `Neutral` consequence. A `PostToolUse`
hook runs it, and syncs the index cells, after an edit under `docs/adr/`
([ADR-0046](0046-edit-time-checks-and-one-verify-gate.md)).
