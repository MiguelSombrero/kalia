# Common failures

An append-only log of the unexpected failures agents hit locally while
working here, one row per occurrence. It exists so that recurrence, which one
session cannot see, survives into the evidence `/quality-sweep`'s
`process-quality` dimension reads ([ADR-0084](adr/0084-an-unexpected-failure-is-logged-as-it-happens-and-counted-by-the-sweep.md)).
Nothing here is a fix: once a failure is understood, its fix goes to its own
home and a row names that home.

**Red CI runs are not logged here.** The sweep collects them itself from
`gh run list`, across every workflow and branch, so no agent has to be
watching. Rows dated before 2026-11-15 hold some; none is added.

**Log a failure** when a tool call or command fails on your machine, and the
cause is tooling, the environment, or a wrong assumption on your part, and it
cost a retry. **Don't log** a product bug that a test caught, a test that is
red on purpose, a failure that is normal operation (`grep` finding no match),
or a problem with the machine itself (a full disk, an emulator that will not
boot) that is no defect of the repository.

**Before you write a row for a failure of the stack itself** (a `5xx`, a slow
request, a red end-to-end test), read its trace with `make trace ID=<trace id>`
or the `kalia-telemetry` MCP server ([README](../README.md#run-locally)), so the
row's **Why** is what the trace showed rather than `unknown`. Starting the
profile is heavy work under `CLAUDE.md`'s two-session cap.

**How to write a row:**

- Append it to the end of the table, on the branch you are working on. Never
  edit or remove an earlier row. If you understand an old row better, write a
  new one.
- **Signature** is the stable part of the error, normalized: the error code
  or message with paths, line numbers, ports and ids removed. Keep it
  verbatim enough to grep. Never paste secrets, tokens or personal data.
- **Why** is your best explanation at the time. `unknown` is a valid answer.
  If the fix already has a home, link it.
- **Cause** is the last column and starts with one of three words;
  `scripts/check-common-failures.mjs` (`make check`) fails a row without one:
  - `external` — the cause is outside the repository's own files: a registry
    or mirror outage, a runner or host tool, or your own slip. It needs no
    owner.
  - `defect, fixed` — the repository was wrong and this branch fixes it.
  - `defect, <owner>` — the repository is wrong and the fix is not here. The
    owner is a quality-backlog ID (`SHOULD-101`), a link to a task file, or
    a [ci-playbook](ci-playbook.md) entry. File the backlog entry in the same
    pull request; a defect that names nobody is found once and lost.
- Don't count, group or deduplicate rows. The sweep does that.
