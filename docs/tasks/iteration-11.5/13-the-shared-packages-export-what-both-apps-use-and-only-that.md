# Task 13: The shared packages export what both apps use, and only that

- **Status:** done
- **Iteration:** [11.5](../iteration-11.5.md)
- **Covers:** none

## Why

`packages/` is meant to hold what is platform-neutral. Three things in it, or
missing from it, do not fit that:

- **`@kalia/api` ties the two apps' React versions together.** It is generated
  with `client: "react-query"` (`packages/api/orval.config.ts`), so it
  peer-depends on an exact `react` (`19.3.1`) and on TanStack Query. Neither
  app imports a generated hook, only the plain functions. Both apps pin
  `react` to that same version today. When an Expo SDK upgrade and a Next.js
  upgrade want different Reacts, the package that is meant to be neutral
  blocks one of them. The hooks it offers would also bypass the feature-owned
  hooks [ADR-0041](../../adr/0041-tanstack-query-feature-owned-hooks.md)
  requires.
- **The web builds its HTTP failures by hand.** It calls
  `apiError("http", …, { status })` at 17 sites in
  `web/features/{catalog,cellar,profile}/api.ts`. The app uses `@kalia/api`'s
  `httpFailure()`, which also carries the response's trace id. `isLocale` is
  written twice (`web/i18n/settings.ts`, `mobile/src/lib/i18n/resolveLocale.ts`),
  next to the `locales` list that both import from `@kalia/locales`.
- **A web client component imports the whole `@kalia/api` barrel to get one
  pure mapping.** `web/components/ui/beer-slot.tsx` and
  `web/features/catalog/BeerDetailsView.tsx` import `beerStyleGroup` from the
  package root, which also exports the transport and the error helpers.

Iteration 12 adds the cellar's reads and writes to the app, and iteration 13
adds the feed and profiles. Each one is another set of calls through this
package, so its shape is cheapest to settle now.

## Scope

- `@kalia/api` carries no peer dependency that neither app uses through it.
- A failure from the API is built the same way in both apps. `isLocale` has
  one home, in `@kalia/locales`.
- A pure mapping such as `beerStyleGroup` can be imported without the
  transport. A boundary rule in each app holds that.
- `packages/README.md` says what each package exports and why.

## Non-goals

- Moving more of the web's or the app's code into packages.
- Changing the generated client's call signatures beyond what the client
  choice forces. The API itself does not change.

## Constraints

- **The generated client is read-only and regenerated by `make api-drift`**
  ([ADR-0012](../../adr/0012-orval-api-client.md)). A change to
  `orval.config.ts` is followed by regeneration, and the drift check passes on
  the result.
- **The style-to-group mapping lives in `@kalia/api`**
  ([ADR-0111](../../adr/0111-the-beer-style-to-group-mapping-lives-in-kalia-api-so-both-clients-colour-a-style-alike.md)).
  A subpath export keeps it in that package rather than moving it.
- **An independent screen imports nothing that can change under an installed
  build** (`independentScreenFiles` in `mobile/eslint.config.js`,
  [ADR-0093](../../adr/0093-the-api-is-additive-only-while-an-app-is-installed-and-a-committed-spec-fails-a-breaking-diff.md)).
  A new export path must not widen what those screens load.
- **Orval's `fetch` client and its options at the pinned version are checked
  in its own documentation or generator output, never from memory.**
- **The web's `mutator.ts` logs the trace id.** Moving to `httpFailure` must
  not log it a second time.
- **Decided at refinement (2026-11-15):**
  - `@kalia/api` is generated with `client: "fetch"`, and both peer
    dependencies are dropped. ADR-0041's feature-owned hooks leave the
    generated hooks no planned use (COULD-120).
  - The web moves to `httpFailure`, logging the trace id once, in
    `mutator.ts`. `isLocale` moves into `@kalia/locales` (COULD-119).
  - The subpath is `@kalia/api/beer-style`. A web client component may not
    import the package root at all. In the app, `beerStyleGroup` is
    imported through the subpath.
  - Whether a test or a fake relies on the generated hooks or on the peer
    dependencies is found when the client is regenerated, and fixed in this
    task.
